1.1한눈에 보기

대상 업무
여러 PDF 자료에서 근거를 찾아 질의에 답하는 업무 (국어연구소 질의 답변 업무에서 출발)
문제
표·이미지 페이지는 텍스트 검색이 되지 않고, 한 질의의 근거가 여러 문서에 흩어져 있음
해결 방식
공개 모델만으로 PDF를 읽고, 키워드·의미 검색을 결합해 근거를 찾은 뒤, 근거가 확실할 때만 출처와 함께 답함
역할
문제 정의, 설계·구현, 평가 설계, 데이터 검증, 결과 분석 (1인)
현재 단계
공개 벤치마크로 평가를 마친 프레임워크. 실제 업무 자료는 보안 검토가 필요해 사용하지 않음

1.2문제와 요구사항

기존 작업의 불편

  • 업무 기록 기준 질의당 평균 약 10분, 주 30건가량 반복
  • 표·이미지 페이지는 목차를 보고 직접 넘겨 확인
  • 한 질의에 PDF 3–4개를 반복해서 열람, 교육과정 개정 때마다 참고 문서 변경

제약

  • 실제 업무 자료는 보안 검토가 필요 → 공개 문서로 개인 프로젝트 분리
  • 보안상 외부 AI 서비스를 쓸 수 없는 환경을 가정

설계 원칙

  • 외부 API 없이 동작: 공개 모델만으로 GPU 1장에서 구동
  • 근거가 확실할 때만 답함: 근거가 없거나 질문의 조건(연도 등)이 근거와 맞지 않으면 보류

1.3핵심 판단

판단선택근거 · 확인 결과
PDF를 어떻게 읽을까텍스트 추출 → 텍스트가 없거나 깨진 페이지는 OCR → 그림·도표 페이지는 VLM이 글로 정리업무 불편의 원인이 "표·이미지 페이지는 검색되지 않음"이었기 때문. 기준 구성은 텍스트 레이어만 읽음
근거를 어떻게 찾을까키워드 검색(형태소 분석 + BM25)과 의미 검색(임베딩)을 결합하고 재정렬임베딩 단독 검색인 기준 구성보다 정답률 +17.1%p. 단, 문서 처리 차이와 함께 측정된 결과
그림·도표 정보를 넣을까채택: 그림·도표 페이지에 VLM 설명 첨부개발용에서 시험하고, 평가용에서 효과가 다시 확인됨
답변 범위를 넓힐까미채택: 표 구조 보존, 근거 기반 추론 허용 프롬프트, 조건 검증을 강화한 상세 프롬프트정답은 늘지 않고 틀린 답만 늘어, "근거가 확실할 때만 답한다"는 원칙을 유지
설정을 언제 채택할까개발용 65문항에서 시험 → 평가용 152문항에서 다시 확인된 것만 채택효과가 실제로 재현되는 개선만 남기기 위함

1.4처리 흐름

기능이 기능이 맡은 역할기술
텍스트 추출 · 품질 검사깨진 텍스트 레이어를 정상으로 판단해 OCR을 건너뛰는 문제를 막음pdfplumber, Tesseract OCR
그림·도표 설명텍스트가 없는 도표 페이지도 검색할 수 있게 내용을 글로 정리Qwen2.5-VL
구조화 · 누락 검증문서·청크 수를 집계해 원본과 누락·중복 없이 일치하는지 확인SQLite (LEFT JOIN, GROUP BY, COUNT·MIN)
하이브리드 검색형태소 단위 키워드 일치와 뜻이 비슷한 표현을 함께 찾음Kiwi + BM25, bge-m3 + FAISS
결합 · 재정렬두 검색 결과를 합치고 질의와의 관련도로 다시 순위를 매김RRF, bge-reranker
답변 생성 · 보류검색된 근거로만 답하고 출처를 표시, 근거 부족·조건 불일치 시 보류Ollama로 공개 LLM 구동 (최종 비교는 Command-R)
자동 채점사람이 매번 판정하지 않아도 같은 기준으로 반복 평가qwen3:14b

1.5평가 결과

평가 설계

  • 1단계 직접 구성한 20문항 (답할 수 없는 질문 포함)
    보류 동작 확인, 연도 표기 인식 오류 발견·수정, 문서·청크 수를 SQL로 원본과 대조
  • 2단계 Allganize RAG-Evaluation-Dataset-KO, 5개 분야 217문항
    개발용 65 / 평가용 152로 나눠 설정은 개발용에서 시험, 평가용에서 재확인

원문 PDF를 구할 수 없는 문서가 있어 전체 300문항 중 217문항으로 평가했습니다.

채점

  • qwen3:14b로 자동 채점
  • 채점 기준을 벤치마크 공식 판정에 맞추고, 30문항에서 공식 판정과 약 93% 일치함을 확인
  • 기준 구성과 이 프레임워크의 답변을 같은 채점 방식으로 채점

1.6오류와 개선

관찰금융 분야 정답률이 낮음
가설"숫자 처리에 약하다"
확인숫자 문항과 다른 문항의 차이 없음. 금융 오답의 64%가 정답 페이지를 찾지 못한 검색 실패
원인 추적실패한 문서를 따라가 문서 처리 오류 4종 발견
수정텍스트 품질 검사 추가, 데이터 교정
검색률 82.9% → 93.4%

발견한 오류 4종

  • 텍스트 레이어가 깨졌는데 정상으로 판단해 OCR을 건너뜀
  • 분할 문서가 전체본으로 저장됨
  • 다른 연도 판본이 수집됨
  • 원본과 쪽 번호가 1쪽 어긋남

평가용 데이터의 오답을 분석하다 발견했기 때문에, 수정 전과 후의 결과를 모두 기록했습니다.

검색 성공과 답변 정확성을 나눠서 봄

  • 금융 분야: 오답 대부분(64%)이 검색 실패 → 문서 처리를 고침
  • 그림·도표 문항: 오답의 절반 이상은 정답 페이지를 찾고도 차트를 해석하지 못함 → 남은 한계로 기록
  • 연도 조건: 1단계에서 연도 표기 인식 오류를 고치고, 질문과 근거의 연도가 다르면 보류하도록 함

3분할 후 영상 5편을 실제 방송 편집본과 비교했습니다. 의미 있는 장면은 찾았지만 구간이 끊겨 맥락이 자연스럽게 이어지지 않는 한계를 확인했고, 이를 후속 연구(B)로 확장했습니다.

실무진으로부터 핵심 장면을 찾는 능력에 대해 긍정적 평가를 받았습니다.

B후속 개인 연구 — 의미 후보와 시청각 신호 결합

왜 결합했나

멀티모달 LLM은 의미적으로 중요한 시점은 찾지만, 구간 경계에 걸리면 맥락이 끊겼습니다. 그래서 역할을 나눴습니다.

  • LLM 의미 후보와 확신도를 제안
  • 음량 · 얼굴 비중 · 화면 움직임 신호 정밀한 구간 위치를 결정

목표

  • 산학 과제에서 확인한 하이라이트 구간 단절 문제 개선
  • 사용자가 기준을 조정하고 결과 근거를 확인할 수 있는 프로토타입 구현
처리 단계 자세히 보기
1신호 점수 산출
  • 오디오 RMS 기반 초 단위 음량
  • 초당 1프레임 얼굴 검출, 신뢰도·화면 점유율 기반 점수 (MediaPipe, 실패 시 대체 검출)
  • 초당 5프레임 Optical Flow 평균 기반 움직임 점수
  • 신호별 0~1 정규화 후 사용자 가중치로 합산 (기본 음량 0.4, 얼굴 0.2, 움직임 0.4)
2중첩 구간 분석
  • 분석 구간을 50% 겹치게 구성해 구간 경계의 하이라이트 누락 방지
  • Qwen2.5-Omni-7B로 구간별 시청각 분석, 사용자 프롬프트를 반영한 시점·확신도 산출
3점수 통합 · 구간 탐지
  • 3초 이내 중복 후보 정리
  • 추천 시점 주변에 확신도 기반 가우시안 가산점을 부여해 신호 점수와 결합
  • 이동평균과 영상별 기준선으로 구간 탐지, 인접 구간 병합
4목표 길이 반영 · 합성
  • 구간 평균 점수 순으로 목표 길이(기본 30초)에 맞게 선택
  • 원본 시간순으로 정렬해 최종 영상 합성

워크플로우와 대시보드

  • FastAPI 영상 업로드, 분석 옵션 입력, 비동기 작업 등록과 진행 상태 조회
  • React · Chart.js 신호 점수, 후보 구간, 점수 기여도, 최종 구간 타임라인 시각화
  • 생성형 AI 활용 백엔드와 대시보드 구현을 생성형 AI로 가속하고, 신호 설계·점수 통합·평가 기준은 직접 설계해 결과 단위로 검증
